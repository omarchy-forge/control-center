# Omaforge Local Control Center

monitor loca development projects

This project was generated by Omarchy Forge as a theme-aware bar widget with a
keyboard-accessible popout.

## Features

- Adapts to top, bottom, left, and right bar orientations through official UI components.
- Uses Omarchy theme, spacing, typography, surface, and border tokens.
- Supports pointer and keyboard operation with a visible focus state.
- Includes loading, success, empty, and error states.
- Runs a local command asynchronously with argument-safe process invocation and a timeout.
- Provides a configurable refresh interval and deterministic fictional demo states.

## Requirements

- Omarchy 4 with manifest schema 1 and Quickshell plugin support.
- The local `date` command used by the starter service.

## Install

Review the source, then install this local checkout:

```bash
omarchy plugin add "$PWD" --enable
```

Plugins execute unsandboxed in the long-lived Omarchy Shell process. Only enable
code you trust.

## Configuration

The `refreshIntervalSec` setting accepts 10–3600 seconds and defaults to 60.
Omarchy persists the value inline in its shell configuration.

## Usage

- Left-click the bar icon to toggle the popout.
- Right-click or middle-click to refresh.
- Press `R` or `Enter` inside the popout to refresh.
- Press `Esc` to close it.

## Development and testing

```bash
./tests/run
```

After reviewing the plugin code and its local commands, run the opt-in isolated
Quickshell entry-point test on an Omarchy machine:

```bash
./tests/runtime --trust-plugin-code
./tests/runtime --trust-plugin-code --state ready
./tests/runtime --trust-plugin-code --state empty
./tests/runtime --trust-plugin-code --state error
# Or, with Forge on PATH:
omaforge dev . --trust-plugin-code
omaforge dev . --trust-plugin-code --state ready
omaforge dev . --trust-plugin-code --state ready --watch
omaforge screenshot . --trust-plugin-code --state ready --output assets/preview.png
```

The runtime test executes the plugin's QML in a temporary HOME/XDG environment
against the installed Omarchy QML modules. It requires `jq`, `quickshell`, an
active Wayland session, and the standard `setsid` and `timeout` commands. It is
deliberately separate from normal checks and generated CI.
The optional `--state ready|empty|error` path exercises fictional in-memory UI
states in the same isolated runtime without persisting data.
Screenshot capture uses the template-declared panel content item and never
captures the desktop. It refuses to overwrite an existing PNG.
Watch mode reruns the same isolated harness after project changes and stops on
Ctrl-C; it does not install the plugin into the live shell.

Only after source review and isolated runtime verification, install the local
checkout deliberately. A GitHub push is not required:

```bash
omarchy plugin add "$PWD" --enable
omarchy plugin list
./demo/run ready
./demo/run empty
./demo/run error
```

Saving files below the installed user-plugin directory triggers shell reload in
the verified Omarchy 4 contract. `omarchy-shell shell rescanPlugins` forces a
rescan when needed.

The demo script uses fictional local data and applies the requested state only
to the running plugin instance through Omarchy Shell IPC. It does not restart
the shell or modify configuration. `Target not found` means the plugin is not
installed and enabled; use the isolated `tests/runtime --state` path first.

## Update

For a Git-managed installation:

```bash
omarchy plugin update omaforge.control.center
```

## Removal

```bash
omarchy plugin remove omaforge.control.center
```

## Privacy and security

This starter runs `date --iso-8601=seconds` locally using array-form arguments.
It performs no network requests, telemetry, credential access, package
installation, `sudo`, or installer hooks. Replace the example command only
after documenting its data access, failure behavior, and timeout requirements.
